# Direct WASM XeTeX with emulated Biber

This isolated experiment compiles the public biblatex sorting example with
WasmTex's direct XeTeX/dvipdfmx WASM engines and CheerpX running native Biber.
JavaScript coordinates passes. No TeX engine or latexmk runs in the emulator.
The end user's browser needs no installed application or TeX distribution.

See [REPORT.md](REPORT.md) for measured results and
[../HYBRID_REVIEW.md](../HYBRID_REVIEW.md) for the implementation review.

## Reproduce

The earlier evaluation supplies:

- The corpus prepared by `latex/benchmark/prepare.mjs`.
- WasmTex checkout `44c5861fcdf729838205b00b96ac9509bc7fb677` and its
  `downloads/manifest-2025.json` in the sibling `wasmtex` candidate.
- The prepared `tinytex-v86/assets/rootfs/opt/tinytex` and the CheerpX ext2
  image/receipt generated by `tinytex-cheerpx/build.mjs`.

Node, Chromium, Poppler, and native XeLaTeX/latexmk/Biber are developer tools
for this benchmark. Native compilation generates test references only.

From the repository root:

```sh
node latex/benchmark/candidates/hybrid-validation/native.mjs
node latex/benchmark/candidates/hybrid-validation/self-test.mjs
node latex/benchmark/candidates/hybrid/run.mjs
node latex/benchmark/candidates/hybrid/summarize.mjs
```

The runner uses HTTP 8706 and Chromium CDP 9706, a fresh candidate browser
profile, and one retained engine/emulator. It replaces this candidate's phase
outputs under `results/biber-sorting/`. Summarization requires successful
native comparisons and the invalid-TeX check. Generated profiles/results are
ignored; `summary.json` preserves measurements and content identities.

## Runtime and resource identity

The engine assets are checked against WasmTex manifest release
`2025-2b3c48691f3cd6d7`, including WASM, worker scripts, and the matching
WASM-dumped format. Engine source receipt:
`0dddc924cc6e69bd2a4b4630e02efe414f84515e`.

The initial attempt used the WasmTex package snapshot
`2025-92e10d3241a312f0` and failed inside biblatex's etoolbox patching code.
The successful run instead serves runtime packages/fonts/configuration from
the frozen TinyTeX-based TeX Live 2025 final tree. The observed WASM format and
native references both use LaTeX 2025-11-01 and L3 2026-01-19; biblatex is 3.21,
and the emulated Biber is 2.21. The WASM ICU data and font-name index remain
supplementary resources from WasmTex's snapshot. Their observed digests, the
local package-tree digest, and all served package digests are recorded.

`tinytex-files.mjs` constructs a static filename lookup with basic format
aliases. Native `.fmt` files are excluded from resolution: the engine must
load its own matching WASM format. This resolver is experimental, with a
simple precedence rule for duplicate basenames; it is not a complete
replacement for every kpathsea search rule.

The benchmark server proxies published WASM resources to satisfy worker
same-origin restrictions and serves the prepared local resources. It compiles
nothing. A product release should build this catalog and mirror verified
assets ahead of time; the benchmark's in-memory index/proxy is not a proposed
production hosting architecture.

CheerpX 1.2.8 loads from its vendor-hosted URL with page attribution. It is not
vendored. The standalone bridge uses an isolated guest directory for each
Biber request, byte transfers, and a warm VM. Only the copy into the IDB
export mount uses guest root; Biber runs as guest UID 1000. This grants no
host filesystem access.

## Behavior and scope

Bibliography invalidation hashes the BCF, all project BIB bytes and names,
configuration, and the fixed Biber runtime identity. It does not use file
timestamps or caller-provided edit labels. A prose edit reuses the BBL.
The loop compares auxiliary contents and diagnostics, with an eight-pass cap.
Each pass clears the prior XDV and rejects fatal diagnostics, so a failed TeX
run cannot be accepted just because an older output exists.

This harness supports one root-level XeLaTeX main file and the fixed fixture
file set. Main-file/environment changes require reload; arbitrary project
file deletion, remote BIB sources, extra backends, and general project
lifecycle handling are outside this experiment. It is not connected to the
LibrePaper editor, and production adapters and offered distributions are unchanged.

The timings are single-machine Chromium observations, not repeated medians.
The package server is local, no deliberate throttling is applied, and native
references are built before the browser run. Local byte counters omit
CheerpX's external runtime and count uncompressed response bodies. They must
not be compared directly with the earlier v86 compressed-download figures.
Safari, Firefox, mobile memory, cross-reload caching, visual PDF geometry,
and source/PDF navigation remain untested.
